# ข้อมูลห้องจริงสำหรับ CP SPACE

ตรวจเมื่อ 15 ตุลาคม 2569 จากปฏิทินสาธารณะ https://me.computing.kku.ac.th/calendar

- SC.09 / อาคารวิทยวิภาส: 18 ห้อง
- SC.06: 10 ห้อง
- รวม 28 ห้อง ความจุ 3–200 คน ใช้ความจุในวงเล็บ ไม่ใช้จำนวนเครื่องคอมพิวเตอร์แทนความจุ
- ชื่อห้อง ประเภท และรายการอุปกรณ์คงตามที่ต้นทางแสดง ไม่เติม Wi-Fi ที่ยังไม่ยืนยัน รูปถ่ายและเวลาเริ่มต้นมีแหล่งที่มา/นโยบายแยกไว้ด้านล่าง

ข้อมูลที่จัดรูปแบบแล้วและแหล่งอ้างอิงรายห้องอยู่ใน `docs/data/computing-rooms-2026-10-15.json` ข้อมูล SC.09 อ่านจาก HAR ที่ผู้ใช้ส่ง ส่วน SC.06 อ่านจากหน้าปฏิทินแยกอาคาร ไม่บันทึกคุกกี้หรือข้อมูลบัญชีจาก HAR ลงโครงการ

## การลบชุดข้อมูลเดิมตามคำขอเจ้าของระบบ

วันที่ 15 ตุลาคม 2569 เจ้าของระบบขอให้ลบข้อมูลเก่าแทนการเก็บแบบเลิกใช้งาน จึงลบห้องเก่า 25 ห้อง อาคารเก่า 3 อาคาร การจองของห้องเก่า 18 รายการ อุปกรณ์ส่วนกลางตัวอย่าง 15 รายการ และการแจ้งเตือน/รายงาน/บันทึกที่อ้างอิงชุดเก่าโดยตรง จากทั้ง command tables และ relational tables เหลือ 28 ห้องจริงใน 2 อาคาร ตรวจผ่าน API ของเว็บแล้ว

เก็บบัญชีผู้ใช้ การเข้าสู่ระบบ การตั้งค่า วันหยุด และประวัติที่ไม่เกี่ยวกับชุดเก่าไว้ สำรองทั้งข้อมูลต้นทางที่ได้รับผลกระทบและ relational tables ลงไฟล์ส่วนตัวใน `tmp/backups/pre-real-only-*.json` ก่อนลบ ทดสอบคำสั่งกับ PostgreSQL สำเนาก่อนใช้จริง และมี guard ตรวจว่าข้อมูลไม่เปลี่ยนหลังสำรอง

`scripts/prepare-real-catalog-cleanup.ts` เป็นเครื่องมือเตรียมสำรองและ SQL สำหรับการลบครั้งนี้เท่านั้น ไม่ใช่การลบอัตโนมัติเมื่อเปิดเว็บ และจะปฏิเสธการใช้ซ้ำเมื่อจำนวนหรือขอบเขตข้อมูลต่างจากชุดที่ตรวจแล้ว การป้องกันแก้ไขรายงานถูกเปิดคืนภายใน transaction เดียวกันหลังลบรายงานเก่าที่ระบุ

ขั้นตอนนำเข้าปกติด้านล่างยังคงรักษาประวัติเมื่อไม่ได้รับคำสั่งลบอย่างชัดเจน

## ชั้นและอาคาร

เวลาให้บริการเริ่มต้นที่เจ้าของระบบอนุมัติเมื่อ 15 ตุลาคม 2569: **08:00–20:00 น. ทุกวัน** อิงกรอบเวลาที่แสดงในปฏิทินต้นทาง ไม่ใช่เวลาทำการที่มหาลัยยืนยัน ตั้งระยะจองล่วงหน้าขั้นต่ำเป็น 0 นาที โดยข้อจำกัดวันหยุด การปิดห้อง ระยะเวลาจอง และการตรวจเวลาทับซ้อนยังใช้ตามระบบเดิม ตัวนำเข้าจะเติมค่าเริ่มต้นเฉพาะห้องที่ยังไม่มีเวลา และรักษาเวลาที่เจ้าหน้าที่ปรับไว้แล้ว

ห้องรหัสตัวเลขใช้หลักที่สองเป็นชั้น เช่น 9227 → ชั้น 2, 6601A → ชั้น 6 โดยระบุ `floorEvidence: inferred-from-room-code` ไว้ชัดเจน ต้องยืนยันกับมหาลัยก่อนอ้างว่าเป็นชั้นที่ตรวจสอบแล้ว ส่วนเลขต่อท้าย `9127-5` ไม่ได้หมายถึงชั้น 5

Audio lab ระบุชั้น 5 ในชื่อห้อง ห้องประชุมเล็กของ SC.06 ระบุชั้น 3 ในชื่อ ส่วนห้องประชุมวิทยวิภาส 3 อยู่ชั้น 3 ตามเอกสารทางการ https://app.gs.kku.ac.th/images/img/admissions/2023-2/3801236.pdf

อาคารทั้งสองมีข้อมูลห้องถึงชั้น 6 ระบบตั้งจำนวนชั้นขั้นต่ำเป็น 6 เพื่อรองรับชุดนี้ ไม่ยืนยันว่าตึกมีทั้งหมดเพียง 6 ชั้น หากอาคารเดิมมีจำนวนชั้นสูงกว่า จะเก็บจำนวนนั้นไว้

## รูปห้องและภาพอาคาร

เจ้าของระบบอนุมัติให้ใช้ภาพอาคารจริงแทนเมื่อยังหาภาพตรงห้องไม่ได้ โดยแสดงป้าย **ภาพอาคาร** บนหน้าค้นหา หน้าจอง และหน้าจัดการห้อง ไม่อ้างว่าเป็นภาพภายในห้อง

- SC.09: ภาพตัวอย่างวิดีโอ “อาคารวิทยวิภาส คณะวิทยาศาสตร์ มข.” ของ Science KKU Channel ใช้สำหรับ 17 ห้อง
- SC.06: ภาพอาคารที่สกัดจากเอกสารประชาสัมพันธ์ของสาขาวิชาสถิติ หน้า 1 ตรวจเทียบกับภาพที่มีป้าย SC.06 ในแผนที่ทางการ ใช้สำหรับ 10 ห้อง
- ห้องประชุมวิทยวิภาส 3: ใช้ภาพกิจกรรมของวิทยาลัยที่ระบุชื่อห้อง ชั้น และอาคารอยู่ในภาพโดยตรง ไม่ใช้ภาพห้องประชุมทั่วไปแทน

เครดิต URL ต้นฉบับ และหลักฐานการจับคู่ภาพอยู่ใน `docs/data/computing-room-photos.json` ภาพเก็บเป็นไฟล์ของเว็บใน `/room-images/` เพื่อให้ไม่พึ่งการโหลดภาพข้ามเว็บ ตัวนำเข้าจะเติมภาพเฉพาะห้องที่ยังไม่มีรูป โดยรักษารูปที่เจ้าหน้าที่ใส่เองไว้ ภาพยังเป็นของแหล่งต้นทางตามเครดิต

## ดึงและนำเข้าใหม่

ใช้ Python มาตรฐาน ไม่ต้องเพิ่มไลบรารี:

```sh
python3 scripts/extract-computing-rooms.py --date 2026-10-15
```

ดึงจากไฟล์ HAR และ HTML ที่บันทึกไว้ได้ด้วย `--har PATH` และ `--html 2=PATH` หาก HAR มีเพียงอาคารเดียว ตัวนำเข้าจะปฏิเสธชุดข้อมูลไม่ครบสองอาคาร

ตรวจแผนก่อน และบันทึกด้วย environment เดียวกับ API:

```sh
node --env-file=.env --import tsx scripts/import-computing-rooms.ts
node --env-file=.env --import tsx scripts/import-computing-rooms.ts --apply
```

ตัวนำเข้าใช้ผู้ดูแลเดิมตามรูปแบบสคริปต์นำเข้าของโครงการ สำรองข้อมูลอาคาร ห้อง รายการจอง และการมอบหมายจาก transaction ที่ล็อกแล้วลง `tmp/backups/` ก่อนแก้ไข ไฟล์สำรองไม่ถูกเพิ่มเข้า Git และจำกัดสิทธิ์อ่าน จากนั้นใช้คำสั่งจัดการเดิมของระบบใน transaction เดียว

- จับคู่รหัสห้องเดิมเพื่อปรับข้อมูล โดยรักษา ID ประวัติ สถานะซ่อม เวลาทำการ และอุปกรณ์ที่เจ้าหน้าที่จัดการไว้
- ไม่เปลี่ยนห้องต่างคณะหรือห้องตัวอย่างให้กลายเป็นห้องจริงคนละแห่ง เพราะจะทำให้ประวัติอ้างอิงผิด
- เลิกใช้งานห้องจากชุดนำเข้าเดิม (`DEMO-*`, `KKU-ED-*`, `KKU-ODT-*` ที่กำหนดไว้) เมื่อไม่มีการจอง PENDING / APPROVED / CHECKED_IN ไม่ลบประวัติ
- ห้องเดิมที่ยังมีการจองค้างจะเก็บไว้ให้เจ้าหน้าที่จัดการ และไม่แสดงในหน้าค้นหา CP SPACE เพราะอยู่นอกอาคารของวิทยาลัย
- เลิกใช้งานอาคารเดิมเมื่อไม่มีห้องที่ยังเปิดใช้งาน
- การรันซ้ำไม่เพิ่มห้องซ้ำ และรายการที่ไม่มีอะไรเปลี่ยนไม่สร้าง audit ใหม่

ไม่ได้นำเข้าช่วง “ไม่ว่าง” ในภาพปฏิทินเป็นรายการจองของผู้ใช้ในระบบนี้ ข้อมูลความว่างจึงยังอ้างอิงการจองภายใน CP SPACE ไม่ซิงก์การจองของมหาลัยอัตโนมัติ เวลาเริ่มต้น 08:00–20:00 ทุกวันถูกเติมครบ 28 ห้องตามคำขอเจ้าของระบบแล้ว โดยใช้ `scripts/set-computing-hours.ts --apply` ซึ่งตรวจรายการจองที่ยังมีผลและเก็บไว้ครบ ผู้รับผิดชอบห้องยังต้องมอบหมายตามนโยบายของระบบ

ชุดข้อมูลใน `apps/web/src/lib/seed.ts` ยังคงเป็นพื้นที่สาธิตและ fixture สำหรับทดสอบ แยกจากฐานข้อมูลใช้งานจริง
