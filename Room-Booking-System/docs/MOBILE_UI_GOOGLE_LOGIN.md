## Google เป็นช่องทางเข้าสู่ระบบเดียว

- ตั้ง `GOOGLE_CLIENT_ID` และ `GOOGLE_CLIENT_SECRET` ฝั่งเซิร์ฟเวอร์ โดยใช้ OAuth client ประเภท Web application
- ตั้ง `APP_ORIGIN` ให้ตรงกับเว็บไซต์ และลงทะเบียน redirect URI `${APP_ORIGIN}/api/auth/google/callback` ใน Google Cloud
- ระบบนี้กำหนด `ALLOW_PUBLIC_GOOGLE=0` และ `ALLOWED_GOOGLE_DOMAINS=kkumail.com,kku.ac.th` อนุญาตเฉพาะอีเมลที่ Google ยืนยันแล้ว พร้อมตรวจโดเมนองค์กร (`hd`) ฝั่งเซิร์ฟเวอร์
- ผู้ดูแลคนแรก: ใส่อีเมล Google ใน `BOOTSTRAP_ADMIN_EMAILS` ก่อนเข้าสู่ระบบครั้งแรก แล้วนำออกหลังตั้งสิทธิ์เรียบร้อย บัญชีใหม่ต้องผ่านการตรวจ Google ที่ยืนยันอีเมลแล้วเสมอ
- API `/api/auth/password/{register,confirm,request-reset,reset,login,set}` ถูกถอดออกและตอบ 404 ไม่มีการออก session ผ่านช่องทางนี้
- คำสั่งสร้างผู้ดูแลด้วยรหัสผ่าน `admin:bootstrap` ถูกยกเลิก เพื่อป้องกันการสร้างบัญชีที่เข้าสู่ระบบไม่ได้
- ไม่ลบข้อมูลบัญชี credentials, password token หรือย้อน migration เดิม บัญชีเดิมที่ยังไม่ผูก Google ต้องให้ผู้ดูแลดำเนินการย้าย identity อย่างตรวจสอบได้ ระบบยังไม่ผูกบัญชีด้วยอีเมลตรงกันโดยอัตโนมัติ

ตั้ง Google Client ID/Secret ในเครื่องแล้วตาม [คู่มือการเชื่อมล่าสุด](GOOGLE_LOGIN_SETUP.md) ปุ่ม Google เปิดหน้าเลือกบัญชีของแอปได้จริง และ API จำกัด @kkumail.com / @kku.ac.th การทดสอบ callback จนได้ session ด้วยบัญชีมหาวิทยาลัยยังรอผู้ใช้เข้าสู่ระบบ

## ความต่างที่จำเป็นจากต้นแบบ

- ใช้ชื่อห้องและการจองจากฐานเดิม ห้องไม่มี `imageUrl` แสดง placeholder แทนภาพห้องอื่น
- วันที่ใช้เวลาประเทศไทย การค้นหาวัน/เวลาตรวจวันหยุด เวลาทำการ การปิดห้อง และคำขอที่ชนกัน
- รอผลบันทึกก่อนแสดงสำเร็จ มีสถานะกำลังทำรายการและแสดงข้อผิดพลาดจาก API
- มีเช็คอิน อุปกรณ์เพิ่ม อีเมลผู้ร่วมใช้ และสถานะ CHECKED_IN / NO_SHOW ตามความสามารถของระบบเดิม
- ปุ่มแนบไฟล์และภาพในต้นแบบเป็นการจำลอง ระบบปัจจุบันยังไม่มีช่องทางบันทึกไฟล์ จึงแสดงสถานะยังไม่เปิดรับอย่างชัดเจน
- เมนูบัญชีเปิดข้อมูลส่วนตัวและเครื่องมือดูแลที่ตรงกับสิทธิ์ โดยไม่เพิ่มปุ่มในเมนูล่าง
- จอ 320px ลดความกว้างช่องเวลาเฉพาะจอเล็ก เพื่อให้อ่านวันที่และเวลาครบ โดยคงตำแหน่งเดิมที่ 390px
- แจ้งเตือนแสดงเหตุการณ์ของข้อความนั้น การยกเลิกภายหลังไม่เปลี่ยนแจ้งเตือนการรับคำขอหรืออนุมัติเดิม
- รายการตรวจสภาพห้องและหมายเหตุบันทึกด้วย INSPECT พร้อมจำนวนอุปกรณ์ชำรุดและสภาพห้องที่ระบบรองรับ

## หลักฐานการตรวจ

- สร้างเว็บและ backend พร้อมตรวจ TypeScript ผ่าน
- ทดสอบธุรกิจ 23 รายการและ backend 44 รายการผ่าน รวมการปิด password API ทุกช่องทาง
- ทดสอบ compiled server handler ผ่าน พร้อม session authorization และการปิด password/test login
- ทดสอบเบราว์เซอร์ด้วย API และ SQLite ในหน่วยความจำที่แยกจากระบบจริง ไม่โหลด environment หรือ credentials ของ cloud
- Mobile: ส่งคำขอ → อนุมัติ → ยกเลิก ผ่าน API 201; วันที่และเวลาค้นหาส่งต่อไปยังฟอร์มจอง; วันหยุดไม่แสดงห้องว่าง; ตรวจสภาพห้องบันทึกผ่าน API 201; ส่งคำถามผู้ช่วย, อ่านแจ้งเตือน และป้องกัน USER เข้าหน้าอนุมัติผ่าน
- Google OAuth เปิดหน้าเลือกบัญชีจริงได้แล้ว; callback จนได้ session ยังรอผู้ใช้ทดสอบด้วยบัญชีมหาวิทยาลัย
