# ผลตรวจฟีเจอร์เทียบเอกสาร วันที่ 12 ตุลาคม 2569

เว็บมีการทำงานหลักเกือบทุกหัวข้อใน SA04.docx และ ASS03-02-Document.docx แต่ยังไม่ครบทุกขั้นตอนตามแผนภาพ และยังยืนยันการส่งอีเมลจริงไม่ได้

ตรวจจากข้อความ ตาราง และภาพแผนภาพฝังในเอกสารทั้งสอง รวมถึง frontend ที่ใช้งานจริงจาก `apps/web/src/main.tsx` → `reference/ReferenceApp.tsx`, backend และกฎใน `packages/core/src` ไม่ถือว่าฟีเจอร์ครบเพียงเพราะพบโค้ดในหน้าจอเก่าที่ไม่ได้อยู่ในเส้นทางปัจจุบัน ไม่แก้โค้ดระบบในการตรวจครั้งนี้

เลข Use Case ในเอกสารไม่สอดคล้องกันทั้งหมด เช่น UC5 ใช้กับทั้งการจองและการยกเลิก จึงเทียบตามชื่อการทำงาน

## ตารางตรวจครบทุกหัวข้อที่พบ

“มีแกนหลัก” หมายถึงพบหน้าจอที่เข้าถึงได้และตรรกะฝั่งระบบ ส่วนอีเมลที่ประกอบอยู่ในขั้นตอนนั้นให้ดูแถวอีเมลแยกต่างหาก ไม่ใช่การรับรองว่าทดสอบบนเว็บ production แล้ว

## สิ่งที่ควรทำให้ตรงเอกสารก่อนระบุว่าครบ

1. ทำให้หน้าค้นหาตรวจวัน/ช่วงเวลาครบก่อนสรุปห้องว่าง แสดงเหตุผลกรณีวันหยุด/ห้องปิด และเพิ่มการเลือกอาคารตามข้อกำหนด
2. ยืนยันพฤติกรรมล็อกวันเวลาในการจองให้ตรง Locked/Read-only และแสดงรหัสการจองเมื่อส่งสำเร็จ
3. เพิ่มรายละเอียดการจองในประวัติ รวมอุปกรณ์/ข้อมูลที่เกี่ยวข้อง และทางเข้าประวัติที่ archive แล้ว
4. เชื่อมผลตรวจอุปกรณ์กับการเปลี่ยนสถานะห้องตามขั้นตอนใน UC9 โดยต้องจัดการรายการจองที่ได้รับผลกระทบด้วย
5. เพิ่มการจัดการชั้นแยก หรือปรับเอกสารให้ระบุการแก้จำนวนชั้นของอาคารซึ่งเป็นพฤติกรรมปัจจุบัน
6. หากต้องทำตาม UC11 ที่ให้ผู้ใช้กรอกอีเมล/เลือกประเภท ต้องเพิ่มหน้าส่งและผลส่ง ปัจจุบันเป็นการส่งอัตโนมัติตามเหตุการณ์
7. ตั้ง SMTP แล้วทดสอบรับอีเมลจริง: คำขอจอง อนุมัติ ปฏิเสธ ยกเลิก ปิดห้อง ไม่เช็คอิน ตักเตือน และระงับสิทธิ์ รวมกรณีส่งล้มเหลว
8. ยืนยัน scheduler/worker บน deployment จริงสำหรับการหมดเวลาเช็คอิน ใน `.env` ที่ตรวจยังไม่มี CRON_SECRET ส่วน `vercel.json` มีการประกาศ cron ไว้แล้ว

เอกสารวาดการค้นหาก่อนเข้าสู่ระบบ แล้วค่อย Google OAuth เมื่อจอง แต่แอปปัจจุบัน `DemoProvider` ให้เข้าสู่ระบบก่อนเข้าทุกหน้ารวมการค้นหา Google client ID/secret มีค่าตั้งใน `.env` แล้ว แต่ไม่ได้ทดสอบ OAuth จริงในการตรวจครั้งนี้ หากลำดับนี้เป็นข้อกำหนดบังคับ ต้องปรับเส้นทาง public search ด้วย

## การตรวจและข้อจำกัด

- `npm test`: ผ่าน 23/23 ครอบคลุมการจองซ้อน จำนวนคำขอ ความจุ วันหยุด การยกเลิก 2 ชั่วโมง ขอบเขตเช็คอิน 30 นาที การปิดห้อง บทลงโทษ และอุปกรณ์ รวมถึงเนื้อหาอีเมลยกเลิก
- ตรวจ `.env` เฉพาะว่ามีค่าหรือไม่ ไม่แสดงค่าลับ ไม่ส่งอีเมล ไม่ใช้ฐานข้อมูลจริง และไม่แก้บัญชีจริง
- การตั้งค่าใน `.env` ของเครื่องนี้ไม่ยืนยันการตั้งค่าใน Vercel/production ไม่ได้ตรวจ deployment หรือรับอีเมลจริงในรอบนี้
- อ้างอิง implementation ที่ใช้งานปัจจุบัน มีหน้าจอเก่า เช่น `features/Rooms.tsx`, `Bookings.tsx`, `HelpProfile.tsx` ส่วน Notifications ซึ่งอาจมีความสามารถเพิ่ม แต่ไม่ได้ถูกเลือกใช้แทน SearchScreen/HistoryScreen/NotificationsScreen ปัจจุบัน
- เอกสารไม่ได้ระบุฟีเจอร์ทุกหมายเลข UC1–UC16 จึงไม่สรุปว่า use case ที่ไม่ปรากฏในสองไฟล์เป็นสิ่งที่ขาด
