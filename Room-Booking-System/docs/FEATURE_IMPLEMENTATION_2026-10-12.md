# ฟีเจอร์ที่เพิ่มหลังตรวจเอกสาร

อ้างอิงช่องว่างที่ระบุใน `FEATURE_COVERAGE_2026-10-12.md` ซึ่งเป็นผลตรวจ **ก่อน** แก้ไข ระบบรอบนี้เพิ่มการทำงานต่อไปนี้แล้วใน source code

| ส่วน | การทำงานที่เพิ่ม |
| --- | --- |
| ค้นหาห้อง | ตัวเลือกอาคาร ตรวจวัน/ช่วงเวลาครบ ระยะเวลา 30 นาที–4 ชั่วโมง ล่วงหน้าไม่เกิน 15 วัน วันหยุด และแสดงสถานะ/เหตุผลห้องปิดหรือถูกจอง ไม่แสดงจำนวนห้องว่างเมื่อข้อมูลไม่ครบ |
| ค้นหาก่อนล็อกอิน | เข้า public search ได้โดยไม่เปิดข้อมูลผู้จอง เก็บห้องและช่วงเวลาที่เลือกไว้ใน sessionStorage แล้วกลับเข้าฟอร์มหลังล็อกอิน รีเฟรชข้อมูลทุก 15 วินาที |
| จอง | ล็อกวัน/เวลาตามผลค้นหา แสดงเลขที่จองจริงหลังสำเร็จ |
| ประวัติ | รายละเอียดการจอง อุปกรณ์ อีเมลผู้ร่วมใช้งาน เหตุผลและเลขที่จอง รวมรายการ archived |
| ชั้น | เพิ่มชั้นถัดไปและแก้ชื่อชั้นแยกจากอาคาร มี ID คงที่และเชื่อมกับหมายเลขชั้นของห้องเดิม บันทึกใน building payload ทั้ง SQLite/Postgres |
| ผลตรวจ | พบปัญหา → MAINTENANCE, ตรวจพร้อมใช้งาน → เปิดกลับจาก MAINTENANCE ต้องยืนยันยกเลิกรายการที่ได้รับผลกระทบ คืนการสำรองและแจ้งผู้จอง ป้องกันการปิดเมื่อมี CHECKED_IN |
| อีเมล | ฟอร์มผู้รับที่ลงทะเบียน/ประเภท/รายการจองหรือข้อความผู้ดูแล ตรวจสิทธิ์และจำกัดจำนวนส่ง ตรวจความพร้อม SMTP แสดงคิว จำนวนครั้ง ผลรับจาก SMTP เวลาและข้อผิดพลาด ผู้ดูแลเห็นผู้รับทุกบัญชี กรองสถานะและลองส่งรายการ FAILED อีกครั้งได้ |
| ความปลอดภัยอีเมล | ใช้เทมเพลตข้อมูลการจองจากเซิร์ฟเวอร์ ผู้ใช้ส่งได้เฉพาะบัญชี/การจองของตน ผู้ดูแลส่งได้เฉพาะบัญชีที่ลงทะเบียน Worker ตรวจโดเมนผู้รับอีกครั้งและหยุด retry กรณีโดเมนผิด |
| โปรไฟล์ | แสดงรหัสผู้ใช้ |

## ตรวจสอบ

- `npm test`: ผ่าน 27 รายการ รวมข้อผิดพลาดช่วงค้นหา ชั้น สิทธิ์ส่งอีเมล และผลตรวจที่กระทบการจอง
- `npm run test:backend`: ผ่าน 47 รายการ รวม HTTP/CSRF สิทธิ์ บันทึกชั้น SMTP readiness outbox และผลส่ง
- `npm run build`: ผ่าน frontend/backend
- เบราว์เซอร์บน fixture ฐานข้อมูลชั่วคราวในเครื่อง: public search → เลือกช่วงเวลา → login session → ฟอร์มวันเวลาล็อก → BOOK → เลขที่จองจาก backend → ประวัติ/รายละเอียด ทดสอบเพิ่มชั้นและ reload แล้วยังอยู่ และฟอร์มอีเมลปิดปุ่มส่งเมื่อ SMTP ยังไม่พร้อม ไม่มี page error ที่พบ
- ตรวจหน้าจอ mobile 390×844 และ desktop 1440×1000 ไม่มี horizontal overflow ที่ตรวจพบ
- ตัวตรวจ Impeccable ไม่พบ primary finding ในหน้าค้นหา/ประวัติและองค์ประกอบฟอร์มใหม่

ชุดเทสต์ audit เดิมปรับให้ตรวจพบ MAINTENANCE แล้วซ่อม/ตรวจพร้อมใช้งานก่อนทดสอบการจองต่อ และเลือกวันทำการถัดไปเพื่อไม่ขึ้นกับวันหยุด 13 ตุลาคม

## สิ่งที่ยังต้องตั้งค่าภายนอกก่อนใช้งานจริง

เลือก Resend และเตรียม `.env.resend.example` กับคู่มือ `EMAIL_SETUP.md` แล้ว แต่ยังไม่มี API key และโดเมนผู้ส่งที่ยืนยัน จึง **ยังไม่ได้ยืนยันรับอีเมลจริง** ไม่มีการส่งอีเมลหรือใช้ฐานข้อมูล production ในการทดสอบนี้

งานหมดเวลาเช็คอิน/ไม่มาและ scheduler มีอยู่แล้ว แต่ยังต้องยืนยัน worker/scheduler บน deployment จริง และตั้ง CRON_SECRET ตามคู่มือ การทดสอบรอบนี้ยืนยันตรรกะและ outbox ภายในเครื่อง ไม่ใช่การรับรอง deployment/OAuth จริง
