# KKU Space — ระบบจองห้องมหาวิทยาลัยขอนแก่น

เว็บ React + TypeScript + Vite เชื่อม NestJS API และ worker เตรียมใช้ Supabase PostgreSQL ผู้ใช้สมัครและตั้งรหัสผ่านเองได้ หรือใช้ Google ทุกอีเมล ธีมดินแดง `#A73B24` พร้อมตราภาษาไทยและฟอนต์ มข.๑ จาก [ชุดอัตลักษณ์ทางการ](https://building.kku.ac.th/downloads/kku-logo/) ดู [ที่มาของไฟล์](docs/BRAND_ASSETS.md)

ค่าปกติเป็น **โหมดเซิร์ฟเวอร์** การจองและสิทธิ์ตรวจบน backend ไม่บันทึกธุรกิจลง browser localStorage มี migration, ตัวอย่าง environment, Docker และ CI แล้ว เชื่อม Supabase กับ API/worker ในเครื่องแล้วตาม [ผลตรวจ](docs/SUPABASE_CONNECTION.md) ส่วน Google Login, SMTP และเว็บสาธารณะยังอยู่ระหว่างตั้งค่า ขั้นตอนเปิดจริงอยู่ใน [PRODUCTION_SETUP.md](docs/PRODUCTION_SETUP.md)

รหัสผ่านเก็บเฉพาะ Argon2id hash ในตาราง private พร้อมยืนยันอีเมล ลืมรหัสผ่าน และเปลี่ยนรหัสผ่าน ดู migration ใหม่และขั้นตอนใน [PASSWORD_AUTH.md](docs/PASSWORD_AUTH.md)

ตรวจการเชื่อมบริการด้วย `npm.cmd run check:connections` โดยไม่ส่งอีเมลหรือแก้ฐานข้อมูล เตรียมค่าลับในเครื่องตาม [CONNECT_SERVICES.md](docs/CONNECT_SERVICES.md)

## เปิดทดสอบเซิร์ฟเวอร์ในเครื่อง

เปิด Terminal ในโฟลเดอร์ `Room-Booking-System` แล้วรัน:

```powershell
npm.cmd ci
Copy-Item .env.development.example .env
npm.cmd run build
npm.cmd start
```

เปิดอีก terminal รัน `npm.cmd run preview` แล้วเข้า http://127.0.0.1:5174/ บัญชีทดสอบมีเฉพาะโหมด development ที่รับการเชื่อมต่อจากเครื่องนี้ เก็บข้อมูลทดสอบใน `var/kku-development.sqlite` การเปิด production ใช้ `.env.example` และ Supabase พร้อม Google/SMTP จริง

```powershell
npm.cmd test          # ตรวจเงื่อนไขธุรกิจ
npm.cmd run test:backend # ตรวจ API, สิทธิ์, transaction และ PostgreSQL migration
npm.cmd run build     # ตรวจ TypeScript และสร้าง frontend/backend
npm.cmd run worker    # งานตามเวลาจริงและอีเมล ต้องใช้ environment เดียวกับ API
```

## โหมดต้นแบบเดิม

หากต้องการชุดสาธิตเดิมในเบราว์เซอร์ ตั้ง `$env:VITE_APP_MODE='demo'` ก่อนรัน `npm.cmd run dev` หรือ build (เปิด dev ที่ 5173) โหมดนี้ใช้ข้อมูลและ localStorage เดิมแยกจากข้อมูลเซิร์ฟเวอร์ วิธีทดลองต่อไปนี้ใช้กับโหมด demo เท่านั้น:

1. เริ่มด้วยบัญชีผู้จอง ณัฐวดี เลือกวัน เวลา และจำนวนคนเพื่อดูห้องว่างทันที ค่าเริ่มต้นเลือกวันนี้และช่วงเวลาถัดไปตามเวลาในชุดสาธิต ลองกด “พรุ่งนี้” แล้วเลือกห้องมอดินแดง ระบุวัตถุประสงค์ ส่งคำขอ ยืมอุปกรณ์และเพิ่มรายชื่อเป็นตัวเลือกเพิ่มเติม
2. เปิด “ตั้งค่าต้นแบบ” ที่ท้ายหน้า เปลี่ยน “ทดลองบทบาท” เป็นเจ้าหน้าที่ แล้วเปิด “พิจารณาคำขอ” อนุมัติหรือไม่อนุมัติคำขอห้องที่ได้รับมอบหมาย
3. กลับเป็นผู้จอง ตรวจสถานะ รายละเอียด ประวัติ และยกเลิกคำขอที่เหลือเวลาอย่างน้อย 2 ชั่วโมง
4. รายการ `BK-2569-0001` อนุมัติแล้วและพร้อมเช็คอินตอนเริ่มเดโม 8 ต.ค. 2569 เวลา 09:10 กดเช็คอินได้ทันที
5. เปิด “เวลาและงานสาธิต” ใน “ตั้งค่าต้นแบบ” ที่ท้ายหน้า เลื่อนไป 10:00 เพื่อจบรอบ หากเริ่มใหม่แล้วเลื่อนไป 09:31 โดยไม่เช็คอิน จะทดลอง no-show ได้
6. เปลี่ยนเป็นผู้ดูแล ทดลองเพิ่ม/แก้ไขห้อง อาคาร อุปกรณ์ บันทึกผลตรวจ ปิดห้องชั่วคราว ดูผลกระทบต่อคำขอ พิจารณาบทลงโทษ และส่งออกรายงาน CSV
7. ผู้จองธนกรมีตัวอย่าง no-show 3 ครั้งสำหรับทดลองตักเตือน/ระงับสิทธิ์ เปลี่ยนบัญชีธนกรเพื่อดูผลสิทธิ์การจอง
8. FAQ เก็บประวัติคำถามในชุดสาธิต การแจ้งเตือนที่ส่งไม่สำเร็จมีปุ่มนำกลับเข้าคิวสำหรับผู้ดูแล เมื่อประมวลผลงานสาธิตจะเปลี่ยนรายการในคิวเป็นส่งแล้ว

ผลทดลองเก็บใน localStorage ของเบราว์เซอร์ กด “เริ่มข้อมูลสาธิตใหม่” เพื่อคืนข้อมูลและเวลาเริ่มต้น

## โครงสร้าง

```text
apps/web/src/
  app/                 # โครงหน้าจอ บทบาท และสถานะชุดสาธิต
  components/          # องค์ประกอบร่วมและแบบฟอร์ม
  features/            # ห้อง การจอง ผู้ดูแล รายงาน FAQ/ข้อมูลส่วนตัว
  lib/domain.ts        # re-export เงื่อนไขธุรกิจร่วม
  lib/api.ts           # เรียก API จริงและป้องกันคำขอซ้ำเมื่อ retry
  lib/mock-api.ts      # ตัวกลางเฉพาะโหมด demo
  lib/seed.ts          # ชุดข้อมูลและเวลาเริ่มต้น
apps/backend/src/      # NestJS API, Google, session, store และ worker
packages/core/         # กฎธุรกิจร่วม frontend demo/backend
packages/contracts/    # ชนิดข้อมูลและคำสั่งร่วม
supabase/migrations/   # schema ใหม่สำหรับ Supabase ไม่แก้ Oracle ต้นฉบับ
tests/                 # ตรวจ workflow และเงื่อนไขธุรกิจ
docs/VERIFICATION.md   # บันทึกขอบเขตการตรวจ
docs/STUDENT_UX.md     # แนวทางและการตรวจหน้าค้นหา/จองสำหรับนักศึกษา
```

## ขอบเขตเฉพาะโหมด demo

- ห้อง ผู้ใช้ อาคาร และภาพประกอบเป็นตัวอย่าง หน้าล็อกอิน/สลับบทบาทเป็นการสาธิต ไม่มีการยืนยันตัวตนจริง
- ไม่มีเซิร์ฟเวอร์ NestJS, Oracle, Google OAuth, AI ภายนอก หรืออีเมลจริง FAQ ตอบจากคำถามที่เตรียมไว้
- ตรวจเวลาทับซ้อนและกันอุปกรณ์จากข้อมูลชุดปัจจุบันในเบราว์เซอร์เดียว อุปกรณ์คืนเมื่อรายการจบ/ยกเลิก/ถูกปฏิเสธ/no-show ยังไม่ใช่ระบบยืมคืนทางกายภาพหรือการจัดการคำขอจากหลายคนพร้อมกัน
- เวลาเดโมคงที่และเลื่อนไปข้างหน้าด้วยผู้ทดลอง งานส่งแจ้งเตือน/no-show/ปิดรอบทำงานเมื่อกดประมวลผล ไม่มี worker จริง
- รายงานชั่วโมงใช้งานเป็นประมาณการจากเวลาเช็คอินถึงสิ้นสุดของรายการกำลังใช้/เสร็จแล้ว ไม่ใช่เวลาครองห้องที่วัดจริง
- ยังไม่ทำข้อเสนอแก้ schema, pending timeout, กฎ lead time 4 ชั่วโมง, และบันทึก late-cancel สำหรับคำขอที่ถูกปฏิเสธการยกเลิก ไม่เพิ่มประวัติความผิดในกรณีนั้น
- ไฟล์ข้อเสนอ `../docs/SYSTEM_ARCHITECTURE.md`, `../docs/DATABASE_REVIEW.md` และไฟล์ SQL/DDL ต้นฉบับใน `../Request` ไม่ถูกแก้ไขจากงานต้นแบบนี้

ขอบเขตโหมดเซิร์ฟเวอร์และรายการที่ต้องตั้งค่าก่อนเปิดจริงอยู่ใน [คู่มือเปิดใช้งาน](docs/PRODUCTION_SETUP.md)
