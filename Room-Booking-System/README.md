# KKU Space — ระบบจองห้องมหาวิทยาลัยขอนแก่น

อัปเดตตาม Term Project: ฐานจริงมี schema `kku_booking` 18 ตารางและ Foreign Key 26 จุด บันทึกพร้อม command data ใน Transaction เดียวกัน เพิ่มบันทึกรายงานย้อนหลังและเลิกใช้งานอุปกรณ์โดยรักษาประวัติ ดู [ผลเทียบข้อกำหนดและการทดสอบ](docs/TERM_PROJECT_COMPLIANCE.md)

เว็บ React + TypeScript + Vite เชื่อม NestJS API และ worker ใช้ Google OpenID Connect เป็นช่องทางเข้าสู่ระบบเดียว หน้ามือถือยึดต้นแบบ `Ui News/booking_room_kku` ใช้สี `#A4233B` และฟอนต์ Sarabun ดู [รายละเอียด Mobile UI และ Google Login](docs/MOBILE_UI_GOOGLE_LOGIN.md)

เวอร์ชันวันที่ **11 ต.ค. 2569** ใช้การเข้าสู่ระบบจริงเสมอ ปิดบัญชีทดสอบแบบเลือกบัญชีโดยตรง พื้นที่จำลองเปิดหลังตรวจ ADMIN session และแยกข้อมูลในหน่วยความจำ ไม่มีการเขียนฐานจริง เตรียม API/cron/security headers สำหรับ Vercel แล้ว แต่ยังไม่ Deploy ตามคำสั่งผู้ใช้ ดู [คู่มือ Vercel และรายการที่ยังต้องตั้ง](docs/VERCEL_SETUP.md)

ข้อกำหนดและนโยบายหลังแก้ทั้งหมดอยู่ใน [สถาปัตยกรรมปัจจุบัน](docs/CURRENT_ARCHITECTURE.md) รองรับ SLA, หมดเวลาคำขอ, จ่าย/คืนอุปกรณ์จริง, inventory/ผลตรวจ, รายชื่อผู้ร่วมใช้แบบอีเมล, เวลาทำการ, FAQ/contact, รายงาน และค้นหาห้องก่อนเข้าสู่ระบบ โดยต้องเข้าสู่ระบบเมื่อจอง

ตั้ง `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` และ callback URL ก่อนเข้าสู่ระบบจริง ผู้ดูแลคนแรกเข้าสู่ระบบด้วยอีเมลใน `BOOTSTRAP_ADMIN_EMAILS` API สมัคร/เข้าสู่ระบบ/กู้/เปลี่ยนรหัสผ่านถูกปิดแล้ว ข้อมูลบัญชีเดิมไม่ได้ถูกลบ

ตรวจการเชื่อมบริการด้วย `npm.cmd run check:connections` โดยไม่ส่งอีเมลหรือแก้ฐานข้อมูล เตรียมค่าลับในเครื่องตาม [CONNECT_SERVICES.md](docs/CONNECT_SERVICES.md)

## เปิดทดสอบเซิร์ฟเวอร์ในเครื่อง

สำหรับพัฒนาแบบอัปเดตโค้ดทันที รันจากโฟลเดอร์หลัก:

```powershell
npm.cmd run dev
```

คำสั่งนี้เปิด API ที่ `127.0.0.1:3001` ก่อน แล้วเปิด Vite ที่ `http://127.0.0.1:5173` และใช้บริการที่เปิดอยู่แล้วได้ กด Ctrl+C เพื่อหยุดเฉพาะ process ที่คำสั่งนี้เปิด ใช้ `npm.cmd run dev:web` หรือ `npm.cmd run dev:api` เมื่อต้องการเปิดแยกกัน

ถ้า Vite แจ้ง `ECONNREFUSED 127.0.0.1:3001` หมายถึง API ยังไม่เปิดหรือหยุดทำงาน ให้ดูข้อความ startup ของ API และตรวจการเชื่อมต่อฐานข้อมูล ไม่ต้องล็อกอินเพื่อเรียก public catalog ส่วน `/api/session` ตอบ 401 ได้ตามปกติเมื่อยังไม่ล็อกอิน

เปิด Terminal ในโฟลเดอร์ `Room-Booking-System` แล้วรัน:

```powershell
npm.cmd ci
# ถ้ามี .env ที่เชื่อม Supabase อยู่แล้ว ให้ใช้ไฟล์เดิม ไม่คัดลอกทับ
# สำหรับเครื่องใหม่ที่ต้องการ SQLite เปล่า: Copy-Item .env.development.example .env
npm.cmd run build
npm.cmd start
```

เปิดอีก terminal รัน `npm.cmd run preview` แล้วเข้า http://127.0.0.1:5174/ เข้าสู่ระบบด้วย Google ไม่มีบัญชีทดสอบเปิดให้อัตโนมัติ ดู [การตั้งค่า Google และผู้ดูแลคนแรก](docs/MOBILE_UI_GOOGLE_LOGIN.md)

```powershell
npm.cmd test          # ตรวจเงื่อนไขธุรกิจ
npm.cmd run test:backend # ตรวจ API, สิทธิ์, transaction และ PostgreSQL migration
npm.cmd run build     # ตรวจ TypeScript และสร้าง frontend/backend
npm.cmd run worker    # งานตามเวลาจริงและอีเมล ต้องใช้ environment เดียวกับ API
```

## โหมดต้นแบบเดิม

ผู้ดูแลที่เข้าสู่ระบบแล้วเปิด **คำแนะนำและช่วยเหลือ → ความพร้อมของระบบ → เปิดพื้นที่ทดสอบ** ได้ `VITE_APP_MODE` ไม่เปิดข้ามการล็อกอินอีกต่อไป วิธีทดลองต่อไปนี้ใช้กับพื้นที่จำลองของผู้ดูแลเท่านั้น:

1. เริ่มด้วยบทบาทจำลองผู้ดูแล เปิด “เครื่องมือทดสอบ” ที่ท้ายหน้า เปลี่ยน “ทดลองบทบาท” เป็นผู้จอง ณัฐวดี เลือกวัน เวลา และจำนวนคนเพื่อดูห้องว่างทันที ค่าเริ่มต้นเลือกวันนี้และช่วงเวลาถัดไปตามเวลาในชุดสาธิต ลองกด “พรุ่งนี้” แล้วเลือกห้องมอดินแดง ระบุวัตถุประสงค์ ส่งคำขอ ยืมอุปกรณ์และเพิ่มรายชื่อเป็นตัวเลือกเพิ่มเติม
2. เปิด “เครื่องมือทดสอบ” ที่ท้ายหน้า เปลี่ยน “ทดลองบทบาท” เป็นเจ้าหน้าที่ แล้วเปิด “พิจารณาคำขอ” อนุมัติหรือไม่อนุมัติคำขอห้องที่ได้รับมอบหมาย
3. กลับเป็นผู้จอง ตรวจสถานะ รายละเอียด ประวัติ และยกเลิกคำขอที่เหลือเวลาอย่างน้อย 2 ชั่วโมง
4. รายการ `BK-2569-0001` อนุมัติแล้วและพร้อมเช็คอินตอนเริ่มเดโม 8 ต.ค. 2569 เวลา 09:10 กดเช็คอินได้ทันที
5. เปิด “เวลาและงานสาธิต” ใน “เครื่องมือทดสอบ” ที่ท้ายหน้า เลื่อนไป 10:00 เพื่อจบรอบ หากเริ่มใหม่แล้วเลื่อนไป 09:31 โดยไม่เช็คอิน จะทดลอง no-show ได้
6. เปลี่ยนเป็นผู้ดูแล ทดลองเพิ่ม/แก้ไขห้อง อาคาร อุปกรณ์ บันทึกผลตรวจ ปิดห้องชั่วคราว ดูผลกระทบต่อคำขอ พิจารณาบทลงโทษ และส่งออกรายงาน CSV
7. ผู้จองธนกรมีตัวอย่าง no-show 3 ครั้งสำหรับทดลองตักเตือน/ระงับสิทธิ์ เปลี่ยนบัญชีธนกรเพื่อดูผลสิทธิ์การจอง
8. FAQ เก็บประวัติคำถามในชุดสาธิต การแจ้งเตือนที่ส่งไม่สำเร็จมีปุ่มนำกลับเข้าคิวสำหรับผู้ดูแล เมื่อประมวลผลงานสาธิตจะเปลี่ยนรายการในคิวเป็นส่งแล้ว

ผลทดลองอยู่ในหน่วยความจำของแท็บและหายเมื่อออกจากพื้นที่ทดสอบหรือโหลดหน้าใหม่ กด “เริ่มข้อมูลสาธิตใหม่” เพื่อคืนข้อมูลและเวลาเริ่มต้น

## โครงสร้าง

```text
apps/web/src/
  app/                 # โครงหน้าจอ บทบาท และสถานะชุดสาธิต
  components/          # องค์ประกอบร่วมและแบบฟอร์ม
  features/            # ห้อง การจอง ผู้ดูแล รายงาน FAQ/ข้อมูลส่วนตัว
  lib/domain.ts        # re-export เงื่อนไขธุรกิจร่วม
  lib/api.ts           # เรียก API จริงและป้องกันคำขอซ้ำเมื่อ retry
  lib/mock-api.ts      # ตัวกลางเฉพาะโหมด demo
  lib/seed.ts          # ชุดข้อมูลและเวลาเริ่มต้น
apps/backend/src/      # NestJS API, Google, session, store และ worker
packages/core/         # กฎธุรกิจร่วม frontend demo/backend
packages/contracts/    # ชนิดข้อมูลและคำสั่งร่วม
supabase/migrations/   # schema ใหม่สำหรับ Supabase ไม่แก้ Oracle ต้นฉบับ
tests/                 # ตรวจ workflow และเงื่อนไขธุรกิจ
docs/VERIFICATION.md   # บันทึกขอบเขตการตรวจ
docs/STUDENT_UX.md     # แนวทางและการตรวจหน้าค้นหา/จองสำหรับนักศึกษา
```

## ขอบเขตเฉพาะโหมด demo

- ห้อง ผู้ใช้ อาคาร และภาพประกอบในพื้นที่จำลองเป็นตัวอย่าง การเปิดพื้นที่จำลองต้องมี ADMIN session จริง การสลับบทบาทเปลี่ยนเฉพาะตัวอย่าง ไม่เปลี่ยน session จริง
- เซิร์ฟเวอร์ตรวจ ADMIN session ก่อนเข้าและก่อนคำสั่งทดสอบ คำสั่งจอง/จัดการในพื้นที่จำลองใช้ข้อมูลในเบราว์เซอร์ ไม่มีการส่งอีเมลจริงหรือเขียนข้อมูลธุรกิจจริง FAQ ตอบจากคำถามที่เตรียมไว้
- ตรวจเวลาทับซ้อนและกันอุปกรณ์จากข้อมูลชุดปัจจุบันในเบราว์เซอร์เดียว มีการบันทึกจ่าย/คืนอุปกรณ์แยกจากยอดกันจอง แต่ demo ไม่รองรับผู้ใช้หลายเครื่องร่วมกัน
- เวลาเดโมคงที่และเลื่อนไปข้างหน้าด้วยผู้ทดลอง งานส่งแจ้งเตือน/no-show/ปิดรอบทำงานเมื่อกดประมวลผล ไม่มี worker จริง
- รายงานชั่วโมงใช้งานเป็นประมาณการจากเช็คอินถึงเวลาปัจจุบันหรือสิ้นสุด อัตราใช้เทียบเวลาทำการที่ตั้งไว้และหักวันหยุด/ปิดห้อง ไม่ใช่เวลาครองห้องที่วัดด้วยอุปกรณ์
- pending หมดเวลาเมื่อถึงเริ่มใช้ห้อง; lead time ตั้งได้รายห้อง ไม่บังคับ 4 ชั่วโมงกับทุกห้อง การยืนยันยกเลิกช้าถูกปฏิเสธและบันทึก `LATE_CANCEL` ครั้งเดียวต่อรายการ โดยคงการจองและยอดกันอุปกรณ์เดิม
- ไฟล์ข้อเสนอ `../docs/SYSTEM_ARCHITECTURE.md`, `../docs/DATABASE_REVIEW.md` และไฟล์ SQL/DDL ต้นฉบับใน `../Request` ไม่ถูกแก้ไขจากงานต้นแบบนี้

ขอบเขตโหมดเซิร์ฟเวอร์และรายการที่ต้องตั้งค่าก่อนเปิดจริงอยู่ใน [คู่มือเปิดใช้งาน](docs/PRODUCTION_SETUP.md)
